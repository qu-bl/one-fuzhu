# AI 资源包操作顺序

`contract.json` 是唯一权威，`generation-profile.json` 是它自动生成的摘要；本文不维护字段、枚举、入口或限制清单。

1. 核验共享契约及 AI 资料的版本和哈希，由 `context-map.json` 加载本轮主题。
2. 同时读取 `resource-package.json`、`main.js` 和真实 Rive 元数据；持久值在 `activate` 恢复，需响应多设备同步时在可选 `onStorageChange(qu)` 中重新读取；缺少资产信息时保留现有名称并说明缺口。
3. 按 `guidance.json` 的资源包场景建立清单、程序、字段、权限、绑定和资产对应关系。
4. 清单与程序作为一次原子交付；普通修改使用精确替换，新建或大幅重写才返回完整文件。
5. 依次执行 JSON Schema、跨文件和宿主校验。失败时逐字保留原始错误并最多修复两轮，仍失败则停止写入。

Rive 列表／嵌套实例集成必须读取契约的 `script.riveInstanceReferences`。
使用会话内真实实例引用进行逐项属性读写、订阅和列表操作，不把 JSON 属性快照当作实例，
不根据属性值或模型名称匹配身份，不用轮询模拟不存在的原生订阅。
旧容器描述仅用于显式整值替换；自动整表回写被拒绝。结构订阅和资源属性能力先查询宿主能力；
普通标量的读写／监听及 Trigger 的事件语义按各端官方 SDK 保持。

Rive 高级操作先读取 `script.rive`：以当前播放器或独立对象的 capabilities 为准，分别使用其参数与生命周期规则。独立文件、共享 Worker、资源解码及离屏输出由官方对象执行；不要创建同名 QVMI 镜像、轮询补通知或假造帧。三种连接方式（JS 直连、清单共享绑定、JS 动态连接）均保留；UI 仍走所属作用域 QVMI。新规则不会为旧客户端安装原生能力。

弹窗只允许组合入口：`presentation: dialog` 的顶层 `components` 都必须为 `group`。
`openUi` 传入该顶层 group 的 id；原子控件只能作为子项，不能单独打开。
更新旧包时同时修改清单和 `main.js`，保留内部控件 id、绑定路径与存档；关闭由业务显式调用
`qu.ui.close()`，不假定存在宿主自动添加的确认、取消或提交过程。
