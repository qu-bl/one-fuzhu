# 千机百变（Qianji Baibian）

> 千机百变不是把动画贴到屏幕上的传统美化工具，而是一套立足 **Rive + JavaScript** 的新一代实时交互范本。它尝试让设计、程序、数据和设备能力汇入同一个轻量运行体系：画面由 Rive 状态机表达，逻辑由 JavaScript 驱动，外部数据通过统一接口进入作品，使每一块屏幕都能够感知、思考、回应并持续变化。

## 一句话定位

千机百变希望把“只能观看的动态画面”推进为“可以运行的交互作品”，让设计师能够创作应用级体验，让开发者不必为每个创意重新制作一套完整应用。

## 为什么它代表新的交互方向

- **Rive 负责生命力**：矢量动画、状态机、数据绑定与实时渲染共同构成可响应的视觉角色，而非预先录制的视频或单纯循环动画。
- **JavaScript 负责思考与行动**：时间、天气、传感器、网络数据、用户输入和宿主能力可以参与逻辑，使作品真正具备行为。
- **资源包负责传播**：画面、脚本、素材、动态 UI 和配置按照统一契约组合为资源包，降低作品制作、分享、更新和跨设备运行的成本。
- **宿主负责系统能力**：文件选择、通知、传感器、网络、窗口和系统交互由原生宿主提供，创作者只描述需求，不重复制造系统组件。
- **云端契约负责长期一致**：资源包、应用脚本、动态 UI 与字段规则由同一套云端规范约束，三端围绕同一事实源演进。

从理论结构上看，Rive 的实时状态机、JavaScript 的开放逻辑和原生宿主能力结合后，其表达上限可以超越传统静态小组件、循环动态壁纸和固定模板工具：它既能是屏幕作品，也能是互动角色、信息面板、轻量工具、设备控制界面或完整体验的入口。

## 设计理念

千机百变追求先进而克制的实现方式：协议尽可能统一，运行链路尽可能短，本地代码尽可能精简，原生系统已有的能力不重复自造。复杂性集中在公开契约与资源内容中，宿主专注稳定运行。项目拒绝用大量补丁维持旧路线，持续收敛为清晰、唯一、可长期演进的技术链路。

它同时坚持本地优先、创作者优先和无广告体验：基础功能不要求应用账号，不植入第三方广告，不进行行为追踪。作品与脚本默认保存在本机，是否启用同步由用户决定。

## 它试图解决的问题

传统屏幕美化通常把设计限制在图片、视频、循环动画、固定模板或少量预设参数中。设计师可以画出漂亮界面，却很难让作品读取实时数据、响应复杂输入、调用系统能力并跨设备持续运行；开发者能够完成这些功能，却往往需要为每个创意重新编写界面、状态管理、文件格式和运行逻辑。创意与工程之间长期存在一条昂贵的鸿沟。

千机百变用 Rive 状态机保存视觉与交互，用 JavaScript 描述逻辑，用 QVMI 连接脚本、Rive 与宿主数据，用 schema-v3 资源包封装作品，再由三端原生宿主提供文件、网络、通知、传感器和窗口等能力。它希望把一次性项目变成可复用内容，把设计稿变成运行时资产，把复杂 App 中的一部分体验变成可独立传播的互动作品。

这种结构同时面向设计师和开发者：设计师保留对动画、状态与交互节奏的控制，开发者可以专注数据与行为，宿主应用负责稳定而统一的系统接入。三者不需要互相侵入对方的职责，作品因此更容易制作、调试、移植、分享和长期维护。

## 与传统方案的区别

- 相比静态小组件，千机百变不仅展示结果，还能持续接收数据、维护状态并响应用户行为。
- 相比循环动态壁纸，它的动画由状态机和实时输入驱动，同一个角色可以根据环境与数据做出不同反应。
- 相比固定模板工具，它允许 JavaScript、资源文件、动态 UI 与宿主能力共同参与，表达空间不被少量预设选项锁死。
- 相比为每个创意单独开发 App，资源包复用统一运行时与系统能力，减少重复工程和发布成本。
- 相比网页容器，它以 Rive 实时渲染和原生宿主能力为基础，更适合持续动画、传感器交互、桌面内容和异形屏幕。
- 相比封闭内容格式，公开契约让 AI、设计师、开发者和第三方工具能够共同理解、生成与检查资源包。

理论上，这套结构兼具互动动画引擎、轻量脚本平台、动态界面协议、内容包格式和跨设备运行时的特征。它的目标并非在旧工具上增加几个选项，而是把屏幕美化、互动内容、轻应用、AI 角色与设备界面收敛到一套可组合的创作范式中。

## 已具备的能力

- Rive 调试台、在线编辑器、数据流检查器与运行时分析仪。
- JavaScript 应用脚本及其运行时。
- schema-v3 资源包制作、导入、运行与分发。
- Rive、JavaScript、动态 UI、QVMI 与宿主能力之间的数据交互。
- 由原生组件呈现的动态 UI，可用于脚本配置、检查器和资源包交互。
- HarmonyOS、Android 与 Apple 三端统一的资源包、脚本和 UI 契约。
- 可选的文件同步与云端规则更新。

## 使用场景

- 会回应触摸、声音、姿态和传感器数据的拟人角色与互动桌宠。
- AI 陪伴角色、对话界面、情绪表达与长期状态呈现。
- 圆屏、长条屏和其他异形屏幕上的时钟、天气、家庭信息与设备状态面板。
- 专注计时、仪表、传感器可视化、快捷控制等轻量工具。
- 智能家居中枢、桌面设备、车载屏幕和定制 Linux 微系统的交互界面。
- 品牌互动展示、数字艺术、展览装置、教育演示和可分发的设计作品。
- 需要在多种设备上保持同一视觉语言与交互逻辑的 App 或硬件项目。

## 对设计师的价值

Rive 设计师可以直接定义画板、状态机、动画混合、输入与数据绑定，让视觉作品保留原本的细腻动效，而不是在工程实现阶段被简化为几张切图。资源包规则允许设计师把 Rive 文件、素材、脚本和配置一起交付，使作品从“展示稿”升级为“可以安装、运行和响应的成品”。

对于 UI 设计师、动效设计师、角色设计师和数字艺术创作者，千机百变提供了一条从视觉创意通往真实设备的短路径。它适合制作互动桌宠、AI 角色、数字伙伴、动态卡片、智能仪表、时钟、天气面板、品牌展示、艺术装置和异形屏幕体验，也适合作为作品集、课程案例和商业定制的交付载体。

## 对开发者与 App 团队的价值

JavaScript 开发者可以在统一运行时中读取和写入 QVMI 数据，处理网络请求、时间、传感器、文件与宿主能力，再把结果交给 Rive 呈现。App 团队无需允许资源包自行绘制系统界面；动态 UI 只描述有限的原子组件、状态与布局，三端使用各自系统提供的原生组件呈现，从而兼顾灵活性、系统规范和维护成本。

对于需要活动页、互动角色、可下载主题、设备面板或用户生成内容的应用，资源包可以成为独立于 App 发版周期的内容载体。对于硬件团队，它可以把设备状态、传感器数据和控制入口转化为具有品牌感和生命感的可视界面。对于教育与培训团队，它可以把 Rive、JavaScript、状态机、数据绑定和交互设计放进同一个可观察、可调试的学习环境。

## 对 AI 创作的价值

千机百变的公开契约把资源包结构、JavaScript 接口、动态 UI、字段类型、必填项、示例和校验规则明确分层，使遵守规则的 AI 模型能够理解任务、选择资料、生成代码并根据宿主原始错误继续修复。AI 不需要猜测每个平台的私有实现，而是围绕同一份云端契约输出资源包清单和脚本。

这使 AI 可以参与脚本生成、资源包骨架生成、动态 UI 配置、Rive 数据绑定建议、错误修复和作品说明编写。项目追求的不是让 AI 绕过规范自由发挥，而是让 AI 在清晰边界内成为设计师和开发者的可靠协作者。

## 精简而先进的工程观

千机百变强调“能由系统提供的，不自造；能由统一契约表达的，不在三端重复硬编码；能由资源包与脚本完成的，不把业务写死在宿主”。动态 UI 使用三端共有的原生控件，样式服从系统默认规范；布局使用自适应和相对关系，避免绝对尺寸；平台独有字段不会阻断资源包的核心运行。

云端规则在一次冷启动周期内按需拉取一次，制作台、检查器和运行过程围绕同一契约工作。QVMI 作为运行时数据空间连接 JavaScript、Rive 与其他来源，状态和事件采用不同语义，资源包身份使用稳定的 `@id`。这些选择共同服务于一个目标：减少重复逻辑、旧技术包裹和长期维护负担。

## 平台与同步

- HarmonyOS：使用系统账号与端云服务同步资源包和应用脚本。
- Android：可使用用户自行配置的 WebDAV 服务同步资源包和应用脚本。
- Apple：使用系统账号与 iCloud 同步资源包和应用脚本。
- 三端使用同一套资源包、应用脚本、动态 UI 与 QVMI 规则；平台独有能力只在相应系统中生效。

## 愿景

千机百变的鸿鹄之志，是让屏幕不再只是信息出口，而成为有表情、有性格、有记忆、能够理解环境并回应人的数字生命载体。项目希望建立一套足够精简、足够开放、足够统一的互动内容基础设施，让优秀设计不再被单一 App、单一设备或单一系统困住。

这不是对现有美化工具的小修小补，而是尝试重新定义互动内容如何被设计、编程、打包、分发和运行。它的最终目标，是让创作者像发布一张图片一样轻松地发布一个可运行的交互世界。

## 常见问题与语义入口

### 千机百变是什么？

千机百变是基于 Rive 与 JavaScript 的互动内容创作、打包和运行平台，也是面向动态屏幕、互动角色、资源包和轻量工具的新一代创作范本。

### 它只是动态壁纸或桌面小组件吗？

不是。动态壁纸与小组件是它可以覆盖的场景之一，但它同时支持状态机、脚本逻辑、实时数据、传感器、动态 UI、系统能力和资源包分发，因此也可以表达 AI 角色、信息面板、互动工具和设备界面。

### 它适合哪些创作者？

它适合 Rive 设计师、动效设计师、UI 设计师、数字艺术家、JavaScript 开发者、App 团队、智能硬件团队、教育者和希望制作互动内容的个人创作者。

### 它为什么强调 Rive + JavaScript？

Rive 擅长实时矢量动画、状态机和数据驱动视觉，JavaScript 擅长业务逻辑、网络与开放数据处理。两者通过统一运行时连接后，可以同时保留设计表现力与程序扩展能力。

### 它有广告或用户追踪吗？

没有第三方广告，也不进行行为追踪。基础功能不要求应用账号，作品与脚本默认保存在本机，同步由用户选择。

### 它是否开放合作？

是。作者正在招募设计师、内容创作者、开发者、App 适配伙伴和硬件合作伙伴，欢迎围绕作品、课程、模板、应用接入、设备界面与生态建设展开合作。
